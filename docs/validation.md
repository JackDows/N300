## 2026-10-22 DeskHub 0.6.1 / 连接恢复

后续复核发现，本节安装版测试由 Codex 子进程启动，数据来自其重定向目录。它没有覆盖用户经资源管理器启动、读取普通 AppData 中旧模块绑定的情况；该遗漏及后续修复见本日 0.6.4 记录。

Release 完整流程通过 73 项/组及类型检查。新增回归覆盖 N300 已保存目标在 Windows 发现缓存失效后的定向扫描、重试及后续连接复用；OG98 生产适配器在首次无响应后等待唤醒、失败写入后只读恢复、主动断开停止重试。桌面测试不再手动连接键盘，改为验证启动过程自动连接。

N300 的连接失败发生在原生 BLE 路径：已保存地址不能保证仍在 Windows 发现缓存中，原逻辑直接重试地址而不重新发现；缓存 GATT 查询失败又提前退出，未进入非缓存查询。修正这两条路径，并显式以共享方式打开控制服务。另一次并行诊断遇到的 `SharingViolation` 在关闭旧控制进程后消失，访问状态为 Allowed，未修改 Windows 权限或蓝牙配置。

实机结果：

- 新 N300 0.1.1 模块连续三次完整退出/重新启动均连接成功，连接及读取完成约 3.5–4.1 秒；保持 AUX、音量 10。
- 安装版 `D:\DeskHub\DeskHub.exe` 0.6.1 使用原有真实绑定，连续三次正常退出/重新打开均自动连接 N300，无手动扫描或连接操作。启动至读取完成约 4.0–7.5 秒；每次退出均确认三个模块进程终止。

- OG98 已应用 0.2.1，接收器存在、键盘无应答时自动重试。用户本轮不方便实体唤醒，**实机唤醒恢复尚未验证**；不将离线故障回归计作硬件通过。
