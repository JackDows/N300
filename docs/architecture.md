# 后端架构

DeskHub 的公共后端是独立 Rust 库 `deskhub-backend`，同一实现也由 `deskhub.exe` 暴露为本地标准输入输出接口。桌面壳可以直接调用库；前端不用维护设备进程、蓝牙或 HID 协议。

## 边界

| 层 | 责任 |
| --- | --- |
| 公共宿主 | 设备绑定、模块包校验、实例生命周期、能力路由、请求超时、状态事件、日志与诊断导出 |
| 每实例控制通道 | 独立的有界队列、工作线程、请求编号、子进程、stdout/stderr 读取线程 |
| 设备模块进程 | 独立协议状态；C++ 硬件工作线程处理该设备的命令和通知；主输入线程处理关闭请求 |
| 原生核心 | 保留已验证的 N300 BLE 和 OG98 HID 实现及回读校验 |

每台设备实例单独分配进程，同型号的多台设备也分别管理。宿主的全局锁仅保护注册表和配置保存，不持锁等待硬件。单个设备中的命令串行，不同设备并行。Windows Job Object 在宿主异常退出时终止所属模块进程。

## 生命周期与故障

`add` 只保存绑定；`start` 启动模块、校验握手并初始化，初始化不打开硬件；`connect` 才连接。`disconnect` 释放设备连接，保留模块进程；`stop` 释放整个实例的运行资源。`restart` 创建新的进程和会话代次，原来已连接的实例会重新连接并读取状态。

模块替换先复制并校验包，启动候选进程，确认清单与实际接口版本一致。预检查失败时旧实例继续运行。通过后提交新绑定、递增会话代次、停止旧进程，再激活新会话。已连接设备会重新连接；连接失败会返回 `replacementActivated:true`，此时新版本已激活，可重试连接。可指定之前的完整模块包再次替换以回退。

每个命令都有请求编号，所有回复和事件都关联设备 ID 与 `generation`。停止、重启、替换后，旧代次的回复不会更新新状态。状态还有递增的 `revision`，前端可忽略乱序的旧快照。

队列最多 32 个等待项。排队过期返回 `queue_timeout` 且 `writeSent:false`，不会终止正在执行的其他操作。执行中的通信超时会结束该设备进程，返回结果不明的写操作不会重放。显式重连后重新读取设备状态。

停止先关闭输入通道，给模块短暂的退出时间，随后终止该模块的 Job。清理等待有上限；极端的系统驱动故障会记录 `cleanup_pending`。进程隔离不意味着蓝牙适配器或 Windows 驱动也彼此隔离。

## 设备与配置

`deviceId` 是稳定的逻辑实例，例如 `speaker`；`label` 是使用名称，例如“桌面音响”；`moduleId` 是协议模块；`target.resourceId` 是物理设备标识。换硬件用 `rebind` 保留逻辑实例，替换模块版本用 `replace` 保留当前目标。

真实设备先扫描，再把候选的 `target` 原样绑定。宿主拒绝将相同 `resourceId` 分配给两个真实实例；当前模块也验证 resourceId 与 BLE 地址/HID 路径一致。模拟设备允许创建多个独立实例。

绑定通过临时文件加原子替换保存；同一数据目录只允许一个宿主写入。模块只读保存的连接配置，不重放旧设备的音量、灯光或其他设置。设备重连后以实际读取值为准。

## 接口与演进

模块协议版本固定为 1，模块自身版本独立。公共宿主不包含 N300/OG98 的命令映射；映射位于各自 `adapter.cpp`。以后可以用其他语言实现同样的本地 JSON 协议，模块构建也通过自己的 `module.ps1` 完成。

当前框架支持本地模块包选择与替换；模块下载市场、独立联网分发及完整桌面 UI 不在本阶段交付范围。
